# 历史设计记录：LightRAG 能力测评平台迭代需求

> 本目录记录的是重构前的设计演进，不是当前产品测评的实现说明。其中的
> `legacy`、`online_baseline`、多实验计划和兼容性分层概念均已不再属于现行
> 产品路径。当前唯一可信的使用说明与目录契约见
> [`memory_eval_tests/README.md`](../../memory_eval_tests/README.md)。

## 产品定位

本平台以生成数据服务构造可控、可追溯的测试语料和 oracle 真值，用来评估
**LightRAG 对文档问答的能力**。文档是测试输入，不是被评分对象。

平台必须能够把一个失败结论定位到以下链路中的某一环，而不能只展示总分：

```text
生成语料与 oracle
  → 文档解析 / 结构保留
  → 切块 / 知识抽取 / 建索引
  → 召回 / 重排 / 证据选择
  → 最终上下文拼装
  → 回答模型输出 / 引用 / 拒答
```

当前的 `memory_data_service`、`memory_eval_tests`、实验注册表和 WebUI 评测
工作台均是本计划的既有资产。计划要求将它们接入同一条可信实验链路，而不是
用新的“文档质量评估”产品替代它们。

## 名词与层级

| 名词 | 含义 | 核心作用 |
| --- | --- | --- |
| 数据场景（Dataset Scenario） | 一次生成的文档、oracle、模板版本和随机种子 | 可控测试输入 |
| 环境配置（Environment Profile） | 服务端保存的 LightRAG、模型、解析和检索配置 | 被测系统版本 |
| 评测计划（Evaluation Plan） | 数据场景、环境配置、实验类型和预算的不可变组合 | 可复现的实验声明 |
| 运行（Run） | 一次计划的实际执行及其全部工件 | 可审计结果 |
| 诊断（Diagnosis） | 基于 oracle 与运行轨迹的逐题失败归因 | 可行动结论 |

模型配置必须按职责拆分：数据生成模型、抽取/KG 模型、Embedding 模型、查询
模型、回答模型、VLM 与 Reranker 不能共享一个含义模糊的 `model` 字段。

## 优先级与迭代顺序

| 迭代 | 优先级 | 名称 | 用户可获得的能力 | 前置依赖 |
| --- | --- | --- | --- | --- |
| [I0](./iteration-0-trust-foundation.md) | P0 | 实验可信性底座 | 知道一次运行实际测了什么、为什么失败 | 无 |
| [I1](./iteration-1-isolated-e2e.md) | P0 | 隔离端到端基线 | 数据集真正入库到指定环境后再测 | I0 |
| [I2](./iteration-2-failure-attribution.md) | P0 | 分阶段失败归因 | 知道 LightRAG 的哪一环导致失败 | I1 |
| [I3](./iteration-3-fair-comparison.md) | P1 | 公平模型与配置比较 | 有效选择外接模型和 LightRAG 配置 | I0、I1 |
| [I4](./iteration-4-dataset-and-scoring.md) | P1 | 数据集与评分可信度 | 知道分数是否泛化、是否值得信任 | I0、I2 |
| [I5](./iteration-5-decision-workbench.md) | P2 | 前端决策工作台 | 低门槛创建、比较与诊断实验 | I0–I4 |

P0 不能降级：若没有真实生效配置、独立索引和失败链路，则任何模型对比都可能
只是“标签不同、执行相同”，不能用于选型。P1 提升实验结论的统计与泛化能力；
P2 将已经可信的能力组织为面向决策的产品体验。

## 跨迭代约束

- 既有数据集、运行报告和实验脚本必须可读；历史结果必须标为 `legacy`，不能
  与新口径的结果默认并列比较。
- 密钥、token、服务端连接串不得写入 `run.json`、日志、导出报告或浏览器。
- 每次运行的输入、环境、产物和失败原因必须可追溯；运行中的任务可取消、重启
  后可恢复查看，且同一任务不得重复执行。
- 任何“模型更优”的 UI 文案必须基于可比实验；未满足比较前提时，UI 必须显示
  不可比原因，而不是给出排名。
- 自动诊断只陈述证据支持的阶段性结论；无法区分模型、提示词或 oracle 问题时，
  必须标为“待复核”。

## 成功指标

- 端到端运行的环境指纹、数据集指纹和入库回执覆盖率为 100%。
- 每个可评分失败 case 至少有一个阶段归因或明确的“待复核”状态。
- 模型比较运行中，100% 满足同数据集、同测试样本、同实验类型和已声明的隔离
  条件。
- 关键数据场景按题型展示指标、样本量、延迟与成本；总分不再是唯一决策信息。
