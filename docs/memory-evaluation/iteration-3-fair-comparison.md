# I3（P1）：公平的模型与配置比较

## 目标

让外接模型和 LightRAG 配置的对比可以支持选型决策。平台必须声明实验单位、可比
前提、重建范围和成本；不满足前提的运行不能进入同一排名。

## 用户故事

- 作为选型者，我希望明确比较的是回答模型、Embedding 模型，还是完整 LightRAG 链路。
- 作为研究者，我希望切换一个变量后，其余变量保持不变，并能复现实验。
- 作为成本敏感用户，我希望在准确率之外比较延迟、吞吐和调用成本。

## 功能需求

### FR-3.1 实验类型与变量约束

平台提供四类明确的计划模板：

| 类型 | 允许比较的变量 | 索引要求 |
| --- | --- | --- |
| 回答模型比较 | 回答 LLM、回答提示词、解码参数 | 复用冻结的最终上下文 |
| 检索配置比较 | 检索模式、Top-K、Reranker、上下文预算 | 复用同一索引 |
| Embedding 比较 | Embedding 模型和向量参数 | 必须独立重建索引 |
| 完整链路比较 | 解析、抽取/KG、Embedding、查询、回答 | 必须独立入库和索引 |

- 计划创建器根据变量变化自动计算执行依赖，并拒绝不合法的复用。
- UI 不再提供含义不明的通用“模型”输入；必须指定模型职责。
- 既有 `custom_arms` 可保留为高级功能，但必须读取模板的变量白名单与依赖规则。

### FR-3.2 冻结上下文回答比较

- 将已有 `frozen_prompt_llm_eval` 纳入正式计划类型。
- 冻结工件必须包含题目、最终上下文、系统/用户提示词、token 预算、温度、采样种子和
  生成参数 hash。
- 所有候选回答模型面对完全相同的冻结输入；模型调用失败与限流需单独统计。

### FR-3.3 可比性校验

- 比较请求自动核对数据集指纹、测试 case 集合、环境版本、实验类型、评分器版本、重复
  次数和预热策略。
- 未通过校验时展示不可比字段，禁止生成排名或“优于”结论。
- 同一比较组支持配对 case 级差异，而不只比较两个总平均值。

### FR-3.4 稳定性、性能和成本

- 计划可设置重复次数、随机种子、并发和预热次数；默认安全值必须写入 manifest。
- 每臂报告质量指标、P50/P95 延迟、入库耗时、成功率、估计输入/输出 token 与可配置
  的成本。
- 报告输出均值、标准差、置信区间或 bootstrap 区间；样本不足时必须显示“证据不足”。

## 非目标

- 本迭代不承诺自动选择唯一最佳模型；推荐需暴露权重和约束。
- 本迭代不绕过第三方模型的配额、限流或隐私策略。

## 验收标准

- 将回答 LLM 与 Embedding 同时放入“回答模型比较”计划时，前端拒绝创建并说明原因。
- Embedding 对比的每个臂拥有不同的索引回执和 storage/workspace 标识。
- 冻结上下文对比中所有模型使用完全相同的输入 hash。
- 报告可显示“质量相近但模型 A 延迟/成本更低”，并显示样本量和波动。
