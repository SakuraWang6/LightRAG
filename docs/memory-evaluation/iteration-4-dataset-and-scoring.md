# I4（P1）：生成数据与评分可信度

## 目标

避免模型因适应生成模板而获得虚高分，并让每个分数的语义、适用题型和不确定性对用户
透明可见。

## 用户故事

- 作为实验用户，我希望知道一个模型是在表格、多跳还是拒答场景中失败。
- 作为数据集维护者，我希望可复现某个数据版本，并知道它由哪个模板和生成模型产生。
- 作为评测使用者，我希望清楚自动评分到底测到了什么，哪些结果需要人工复核。

## 功能需求

### FR-4.1 场景分类与数据集版本

- 数据集 manifest 增加场景标签及题型配额：单跳、多跳、表格、公式、图像、跨页、
  干扰事实、矛盾事实、近似数值、否定问法、不可回答等。
- 记录生成器代码版本、模板版本、生成模型/provider、随机种子、输入参数和 oracle
  schema 版本。
- 同一配置和随机种子必须可复现相同数据集指纹；非确定性生成需记录可追溯请求 ID。

### FR-4.2 抗模板泄漏的数据策略

- 为关键题型提供问法改写、实体别名、语序变换、跨文档组合和干扰证据变体。
- 训练/调参集合与冻结验证集合必须按数据集版本和场景显式隔离。
- 报告按场景分层展示，禁止仅通过总平均分宣称系统能力。

### FR-4.3 评分器分层

- 保留确定性规则评分：数值/单位、公式、表格单元、拒答、稳定 ID 引用。
- 新增可替换的语义答案评分器接口；每次结果记录评分器名称、版本、输入和判定理由。
- 对可能存在多种正确表述的题，评分结果支持 `pass`、`fail`、`uncertain`，不能强制二分。
- 建立抽样复核集：人工或独立判别器复核自动评分样本，并报告一致性和误差方向。

### FR-4.4 指标解释与统计

- 指标在 UI 与报告中携带精确定义、分母、适用范围和已知局限。
- 按题型输出样本数、均值、区间、缺失/待复核数量；abstain、对象级指标等不可适用项
  不得被静默记为零。
- 各指标必须区分“证据在候选中”“证据在最终上下文中”“回答有正确引用”。

## 非目标

- 本迭代不要求生成的数据完全取代真实业务语料。
- 本迭代不将 LLM 裁判视为无误差的黄金标准。

## 验收标准

- 任一数据集可追溯到生成器、模板、模型与种子版本。
- 报告至少按三种场景分层展示，且显示每层样本数。
- 评分器对模糊答案能够输出 `uncertain` 并进入复核队列。
- 抽样复核报告展示自动评分与复核结果的一致性，而非只展示自动总分。
